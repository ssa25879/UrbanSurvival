# Urban Survival 패치 계획 (1.0.1 ~ 1.0.4)

- 작성: 2026-10-08. 목적: 비공개 테스트 기간에 작은 업데이트를 여러 번 올려 Play Console 업데이트 내역을 쌓는다(사용자 지시).
- 원칙
  - 패치 하나에 주제 하나. 실제로 들어간 변경만 출시 노트에 쓴다(`release-notes.md`).
  - 버전마다 `ProjectSettings`의 `bundleVersion`(표시 버전)과 `AndroidBundleVersionCode`(1씩 증가)를 올린다. 같은 업로드 키(`UrbanSurvival_user.keystore`)로 서명한다.
  - 빌드는 사용자가 요청할 때만 만든다. 빌드 뒤 매니페스트 권한 0개를 다시 확인한다.
  - 비공개 테스트 트랙에 올린다. 트랙에 새 버전을 올려도 테스터의 참여(옵트인)는 유지된다고 알려져 있지만, 14일 요건 계산에 영향이 있는지는 Play Console 안내로 확인한다(미확인).
- 기준: 1.0.0(코드 1)은 `ab09266`. 2026-10-08 현재 그 뒤 코드·자원 변경은 아이템 자석 연출(`23fb6ea`)과 EmojiOne 제거(`918b160`)다. 1.0.1 구현은 에디터 세션(세션 1)이 진행 중이며 역할 분담은 `WorkNotes/Collab.md`(Git 밖) 2026-10-08 절.

## 빌드 없이 스토어에서만 하는 것
- 영어 스토어 등록정보 추가(`Builds/PlayUpload_1.0.0/3_문안/en_*`) → 그다음 패치부터 출시 노트에 `<en-US>`도 넣는다.
- 스크린샷 개선(02·03 플레이어가 좀비 떼에 묻힘, 05 최종 보스가 화면 밖).

## 패치 하나를 올리는 순서
1. 해당 버전 항목 구현·검증(에디터 플레이, 필요하면 기기) → 커밋.
2. `bundleVersion`·`AndroidBundleVersionCode` 올리기(자동 재저장 변경과 섞지 말고 이 두 줄만 커밋).
3. 사용자 요청 시 AAB 빌드(업로드 키) → 권한·버전 확인.
4. `release-notes.md`의 해당 절 상태·기준 커밋 기록 → Play Console 비공개 테스트에 업로드, 출시 노트 붙여 넣기(화면 절차는 `play-console-upload-guide.md` 8장).
